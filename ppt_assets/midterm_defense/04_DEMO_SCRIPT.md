# 中期答辩演示脚本

## 一、推荐演示顺序

1. 打开 dashboard 首页
2. 介绍健康评分和状态分布
3. 启动实时生成器，演示持续流量注入
4. 播放演示模式
5. 切到异常明细和服务热力榜
6. 展示事件回放
7. 保存基准，再做一次对比分析
8. 展示历史快照
9. 导出报告

## 二、现场讲解重点

### 1. 首页总览
- 健康评分体现系统整体状态
- 热门路径说明流量集中位置
- 状态分布反映错误/成功比例

### 2. 实时生成器
- 选择健康流量、错误突增或延迟抖动
- 点击开始注入，观察仪表盘实时刷新
- 说明这部分复用了统一 `/ingest` 接口，后续可以接真实服务输出

### 3. 演示模式
- 正常流量
- 错误突增
- 延迟升高
- 恢复阶段

讲解时要强调：系统不仅能“看结果”，还能“演示过程”。

### 4. 异常下钻
- 从总览到异常明细
- 从异常明细到服务热力榜
- 从服务热力榜到事件回放

### 5. 对比分析
- 先设一个正常基准
- 再导入错误样本
- 直接讲错误率和 P95 变化

### 6. 历史快照
- 展示系统记住了哪些分析节点
- 说明后续可继续发展成历史复盘能力

## 三、推荐终端辅助命令

### 健康检查

```bash
curl http://127.0.0.1:3000/health
```

### 查看指标

```bash
curl http://127.0.0.1:3000/metrics
```

### 查看告警

```bash
curl http://127.0.0.1:3000/alerts
```

### HTTP 实时推送

```bash
curl -X POST http://127.0.0.1:3000/ingest \
  -H 'Content-Type: application/json' \
  -d '{"content":"{\"path\":\"/api/orders\",\"status\":200,\"latency_ms\":42}\n{\"path\":\"/api/orders/checkout/payment/callback\",\"status\":503,\"latency_ms\":280}"}'
```

## 四、最适合现场展示的两个场景

### 场景 A：错误突增
- 错误率明显变化
- 异常明细最直观
- 服务热力榜容易讲

### 场景 B：延迟升高
- P95、P99 变化明显
- 事件回放展示效果好
- 对比分析有说服力
