# 项目变更兼容记忆

## 一、用途

这个文件用于固化 `logscope` 项目后续迭代时的默认约定，避免功能更新后出现：

- 旧命令失效
- 演示脚本与实际行为不一致
- 前端页面没有同步后端变更
- 答辩材料和项目真实状态脱节

它不是一次性的说明，而是本项目后续持续维护时的固定记忆。

## 二、默认规则

后续每次新增、修改或重构功能时，默认执行以下动作：

1. **兼容已有命令**
   - 优先保持 `README.md`、`demo.sh`、`cases/README.md` 中已有命令继续可用
   - 如果必须调整命令行为，要同步更新文档并补充新的示例

2. **回归验证旧命令**
   - 每次更新后，至少回归验证之前已经公开给用户或用于答辩展示的命令
   - 尤其要检查：
     - `./demo.sh tcp-server`
     - `./demo.sh gen-error`
     - `./demo.sh gen-latency`
     - `./demo.sh gen-wave`
     - `./demo.sh metrics`
     - `./demo.sh alerts`
     - `POST /imports`
     - `POST /ingest`

3. **同步更新前端逻辑**
   - 只要后端接口字段、告警逻辑、统计窗口或演示模式发生变化，前端页面必须同步适配
   - 特别要检查：
     - 仪表盘字段展示
     - 活动告警面板
     - 样例切换与演示模式
     - 实时生成器
     - 中英文文案

4. **同步更新项目材料**
   - 功能变化后，要同步更新：
     - `README.md`
     - `cases/README.md`
     - `ppt_assets/midterm_defense/`
   - 确保运行命令、演示路径和答辩说法一致

## 三、推荐回归顺序

每次更新后，建议按下面顺序自检：

1. 语法与测试
   - `bash -n demo.sh`
   - `node --check web/app.js`
   - `cargo test`
   - `./scripts/regression_check.sh`

2. 服务基础能力
   - `GET /health`
   - `GET /metrics`
   - `GET /alerts`

3. 导入与实时注入
   - `POST /imports`
   - `POST /ingest`

4. 演示命令
   - `./demo.sh tcp-server`
   - `./demo.sh gen-error`
   - `./demo.sh gen-latency`
   - `./demo.sh gen-wave`

5. 前端展示
   - 首页是否正常加载
   - 指标是否刷新
   - 告警是否显示
   - 演示模式与实时生成器是否可用

## 四、需要特别避免的问题

后续修改时，默认避免出现以下情况：

1. 后端真实告警逻辑变了，但前端仍读取旧字段
2. 演示命令还能运行，但展示效果已经不符合命令名称
3. 生成器时间戳或节奏不合理，导致滚动窗口和告警失真
4. README 里的命令和当前版本行为不一致
5. 中期/结题答辩素材仍停留在旧实现上

## 五、结论

一句话记忆：

> 每次更新后，都要兼容之前的命令支持，回归验证关键演示链路，并同步更新前端逻辑与答辩材料。
